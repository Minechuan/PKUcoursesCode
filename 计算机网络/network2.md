# 计算机网络复习


## 第四部分：网络层

### 4.1 基本概念
网络层：主机和主机之间通过多跳传输数据包
功能：
1. 转发：路由器根据路由表决定数据报的输出接口（转发函数）
2. 路由：确定从源主机到目的主机的路径（路由算法协议）

数据平面：实现数据报的转发功能，每个路由器独立
控制平面：全网计算，涉及多个路由器
   * 传统路由算法：多个路由器分布式协作计算
   * SDN：集中式控制器计算，路由器执行；软件定义网络中心化控制平面，每个路由器上维护一个 CA（control agent）


### 4.2 路由器架构


#### 控制平面与数据平面划分

1. 控制平面：运行各种路由协议，计算的转发路径储存在**路由表**中
硬件 CPU，除了运行路由算法，还运行 **网络管理功能**，如 SNMP 协议
2. 数据平面：根据路由表转发数据报
ASIC 专用硬件，处理速率高

路由管理选择最佳路由，形成核心路由表，转发到数据层形成转发表（FIB: Forwarding Information Base）

#### 数据平面
IP 报文经过路由器：链路层封装更新， TTL 减 1，校验和更新
数据平面组成：
1. 输入端口：接口卡，链路层解封装，检查错误，TTL 减 1，校验和更新
   1. 输入端口存储转发表
   2. 每个输入端口独立处理计算任务
   3. 排头阻塞：队列头的数据报阻塞后续数据报的发送，即使对应的链路资源是空闲的
2. 交换结构：交换缓冲区数据报转发到输出接口卡
3. 输出端口：接口卡，链路层封装，发送数据报
   1. 输出端口主要负责缓冲、队列管理和链路层发送。
   2. 每个输出端口维护一个队列存储等待发送的数据报
   3. 转发策略：
      1. 基于目的地址的转发：只根据目的 IP 地址查找路由表；**最长前缀匹配**
      2. 通用转发：根据数据报中的任意字段组合查找路由表

#### 交换结构

交换速率：所有从输入端口到输出端口的总和
交换结构分类：
1. 共享内存：由控制平面的 **路由处理器** 控制内存读写
   1. 报文到达输入端口时，产生中断，路由处理器将报文从输入端口读入内存
   2. 输入端口查表后把 **数据包在内存中的地址（指针）** 写给输出端口的队列。
   3. 输出端口写入缓冲队列
   4. 问题：连续的内存拷贝效率低
2. 共享总线
   1. 通过输入端口转发表给报文贴上标签，表明输出端口
   2. 广播至所有端口
   3. 每个输出端口检查标签，若匹配则接收报文
   4. 缺点：总线一次只能广播一个报文
3. Crossbar 交换结构
   1. 使用 2N 条总线连接 N 个输入端口和 N 个输出端口
   2. 可以并行工作

#### 输出端口
也有缓冲队列
队列调度的两种方式：
1. 性能考虑：选择对网络性能最好的报文
2. 依据公平性选择报文

交换机的报文分为 N 个流，链路带宽 C，N 个流共享带宽 C
缓冲区大小：$\frac{RTT*C}{\sqrt{N}}$

**调度机制**
1. 先进先出（FIFO）：简单，但不能区分不同流
2. 优先级调度：高优先级流优先发送；多个队列对应不同的优先级。但是损失了公平性
3. 轮询调度：按照报文分类，进入多个队列，在队列间轮询
4. 加权公平队列：（在轮询调度的基础上）每个队列拥有权值，轮询时考虑队列的权值


### 4.3 IP 报文和 IP 地址

报文格式不直接考；
* 源地址和目的地址：32 位二进制数
* 首部校验和：16 位，检测首部出错
* 生存时间 TTL：8 bit 防止报文在网络中无限循环
* 标识：16 bit 标识 *分片的报文* 属于同一个原始报文
* 标志：3 bit 分片控制，例如是否允许分片、是否为最后一个分片

#### 数据报分片

**MTU**最大传输单元：链路层协议允许传输的最大数据报长度
分片策略：允许途中分片，不允许途中分片
重组策略：Internet 采用**目的端重组**；重组需要的信息：原始数据报编号、分片偏移量、是否收集所有分片
原始报文和分片报文具有相同的 IP 头部字段，

#### IP 地址
接口：连接主机/路由器与物理链路之间的模块
每个接口对应一个 IP 地址
1. IP 地址由网络号和主机号组成，网络号为地址的前缀；
2. 有相同网络地址的网络接口构成子网
3. 子网使用子网掩码表示

>**CIDR（Classless Inter-Domain Routing）**
网络地址可以是任意长度
>1. CIDR 子网内的地址可以进一步划分为多个子网：地址聚合、路由聚合
>2. 子网可以通过更改路由规则进行迁移。
>3. 根据路由选择子网时使用最长前缀匹配-> 子网掩码的最长匹配项

**子网内的 IP 包转发**：
1. 根据 IP 地址（网络层路由器）意义不大。
2. 根据 MAC 地址转发（链路层交换机）：子网实际使用

如果目的 IP 地址在本子网内，将 IP 数据报封装为链路层帧，发送到目的主机。事实上，主机通过 ARP 协议获取目的主机的 MAC 地址。
如果想要发送到子网外的主机，主机将数据报发送到子网的 **网关路由器接口** ，路由器再转发数据报。主机发出的网络层数据报的目的地址仍然是最终目的主机的 IP 地址，而不是网关路由器接口的 IP 地址。


### 4.4 基本网络层协议

#### ARP（Address Resolution Protocol） 协议
**主要应用场景**：子网内数据传输，向子网外传输数据时，仍然需要通过 ARP 获取网关路由器接口的 MAC 地址。

管理 IP 地址和 MAC 地址的映射关系（主要运行在主机中，路由器（每一个端口）中，而不是交换机）
主机也可以通过 ARP 获取同一子网内其他主机或路由器接口的 MAC 地址
过程：
1. 如果 A 的ARP 表中没有 B 的 MAC 地址，A 广播*包含 B 的 IP 地址的 ARP 请求帧*。
2. B 收到请求帧后，发送*包含自己 MAC 地址的 ARP 响应帧*给 A。
3. A 收到响应帧后，更新 ARP 表。

向子网网关路由器接口发送数据时，仍然使用 ARP 解析网关的 MAC 地址。
**ARP Spoofing** 攻击：攻击者发送伪造的 ARP 响应帧，欺骗主机更新 ARP 表，将截获受害者的数据。

#### DHCP（Dynamic Host Configuration Protocol）协议
ICANN(IP 管理机构) 分配给 ISP 一块 IP 地址空间，ISP 再分配给用户
路由器、服务器申请 IP 地址采用静态设定
动态获取：使用 DHCP 协议

DHCP 过程：
1. 客户从 UDP 端口68通过**广播**发送 *DHCP 发现报文*
2. DHCP 服务器**单播或广播** *DHCP 提供报文* 给客户
3. DHCP 客户从多个 DHCP 服务器中选择一个，**以广播形式**发送 *DHCP 请求报文*
4. 被选择的 DHCP 服务器**单播或广播**发送 *DHCP 确认报文* 给客户

安全问题：
1. DHCP 耗竭攻击：攻击者发送大量 DHCP 发现报文，耗尽 DHCP 服务器的 IP 地址池
2. 流氓 DHCP 服务器攻击：攻击者设置伪造的 DHCP 服务器，向客户分配错误的 IP 地址和网关

#### NAT（Network Address Translation）协议

目的：解决 IPv4 地址不足问题，将私有 IP 地址映射为公共 IP 地址
所有从本地网络发出的报文具有相同的单一源公共 IP 地址，使用不同的源端口号区分

**工作机制**
1. 发数据报，NAT 路由器将私有 IP 地址和端口号映射为公共 IP 地址和端口号更新 NAT 转换表
2. 收到返回数据报，NAT 路由器根据目的端口号查找 NAT 转换表，恢复为私有 IP 地址和端口号

**NAT 的优势**
1. 节省公共 IP 地址
2. 灵活连接Internet
3. 保护子网的内部结构

**NAT 的缺点**
1. 违反了 IP 的分层模型（因为网络层协议本来不应该依赖端口号）
2. 不能处理 IP 报头加密
3. 新型网络应用要考虑 NAT 场景，从而增加复杂性

#### ICMP（Internet Control Message Protocol）协议

允许路由器和主机报告差错情况和网络异常
ICMP 报文封装在 IP 数据报中

类型：
1. 差错报告报文：主机不可达、网络不可达
2. 询问报文：Echo 请求和 Echo 应答（ping 命令）

**实现 Ping**
Ping 用来测试两个主机之间的连通性
1. 发送方发送 ICMP Echo 请求报文
2. 接收方收到请求后，发送 ICMP Echo 应答报文
3. 发送方收到应答后，计算往返时间

利用 Ping （接收到的剩余 TTL）判断操作系统的类型：不同操作系统设置的 TTL 不同

**Traceroute 与ICMP**
使用 TraceRT 命令确定从源主机到目的主机的路径
1. 源主机发送一系列 TTL 递增的 ICMP 回显请求报文(不可能的端口号)
2. 当第 n 个路由器收到 TTL=n 的报文时，TTL 减 1 变为 0，丢弃该报文，并发送 ICMP 超时差错报文给源主机，这个报文中的源地址就是该路由器的地址

停止条件：由于报文的目的端口不可达，最后报文到达目的主机后，目的主机发送 ICMP 目的不可达报文给源主机，源主机得到该 ICMP ，停止探测。

### 4.5 路由算法

*利用网络的图抽象，介绍 IGP 中使用的两种基本路由算法：距离向量和链路状态*

#### 距离向量
Bellman-Ford 算法：
1. 每个节点维护一个距离向量，包含到达所有节点的距离
2. 每个节点周期性地将自己的距离向量发送给邻居节点
3. 每个节点根据邻居节点的距离向量更新自己的距离向量

实现数据的分布式和计算的分布式；最终每个结点储存了一个 n*n 的距离矩阵
**算法特点**：
1. 异步：迭代频率不需要一致
2. 事件驱动：每个结点迭代触发：
   1. 本地链路代价发生改变
   2. 收到邻居结点的距离向量
3. 分布式：
   1. 结每个结点当且仅当 DV 发生变化时才通知其他节点
   2. 邻居结点根据需要通知其他结点

**特点**：好消息快速传播，坏消息慢（无穷计数问题）
**毒性逆转**：如果节点 a 到达 c 的下一条为 b ，则 a 将通知 b : a 到 c 的距离为无穷大。
无法解决一般性无穷计数的问题

#### 链路状态算法
每个结点都知道网络拓扑和链路开销
每个结点计算以自己为源，基于 Dijkstra 算法计算到其他所有节点的最短路径，生成该节点的转发表。

**距离向量和链路状态比较**
1. LS 发送 O(nE) 条消息；DV 取决于收敛速度
2. LS 每个结点 O(n^2) 或  O(nlog n) 时间完成计算；DV 不确定
3. 链路或路由器故障对 LS 影响较小，对 DV 影响较大

#### 层次路由
*介绍自治系统（AS）和 AS 之间传输的协议*

庞大的路由表难以查询，之前提到过通过地址聚合减少路由表大小
但是现实中地址往往是不连续的
**层次路由**：由多个自治系统（AS）组成，每个 AS 内部使用单一的路由协议，AS 之间使用另一种路由协议，每个 AS 可能包含多个子网。
IGP(Interior Gateway Protocol)：OSPF(Open Shortest Path First)、RIP（Routing Information Protocol）
EGP(Exterior Gateway Protocol)：BGP

**AS 之间要解决的问题**
1. 各个 AS认可的链路代价不同（商业利益和策略立场的根本差异）
2. 不仅决定流量发往何处，还要决定哪些流量可以发往自身
AS 之间最短缺乏共识，许多 AS 之间“最短”未必是最优的

**BGP（Border Gateway Protocol）**
目前互联网中唯一实际运行的自治域间的路由协议
BGP 的功能：
1. eBGP：从相邻的 AS 获得网络可达信息
2. iBGP：将网络可达信息传播给 AS 内的路由器
3. 基于网络的可达信息和策略决定到其他网络的“最优”路由

**AS 边界路由器**：运行 eBGP 和 iBGP 和 IGP 协议；在绝大多数网络中：AS 边界路由器 = 运行 eBGP 的 BGP 路由器
1. 边界路由器通过 eBGP 学到外部前缀
2. 边界路由器通过 iBGP 将该前缀传播给 AS 内其他路由器
3. 内部路由器：
   1. 通过 iBGP 选择“用哪个 **出口** ”
   2. 通过 IGP 计算“到该出口的路径”


**BGP：路径通告**
BGP 路由器之间建立 TCP 连接，交换 BGP 报文；“AS3， X” 表示 AS3 承诺会帮助转发通往 X 的数据包
BGP 路径属性：AS 路径需要经过的所有 AS 号、下一跳对应的 IP 地址
路径通告开销：自治系统的数量级
BGP 为每个 AS 提供：
1. 从邻居 AS 获取网络的可达信息
2. 传播可达信息给所有的域内路由器
3. 根据可达信息和策略决定路由

**AS 间策略**
1. 路由器使用策略决定接受或拒绝某条路径通告
2. 路由器使用策略决定是否向邻居 AS 通告某条路径

**AS 内选择**（根据 iBGP）:选择最近的 BGP 出口，最小化报文在 AS 的停留时间

### 4.6 广播和组播路由

广播：源主机同时给全部目标地址发送同一个数据包
实现方法：flooding:(受控制的)，否则出现广播风暴，路由器收到多个副本

**序号控制泛洪**:*序号表* 记录是否收到过
1. 广播数据包 X 从端口 1 到达 R
2. R 检查数据包的来源 S 和广播序号 n，对比 R 的*序号表*
3. 如果有记录：丢弃；否则在序号表中记录 S 和 n，将数据包从其他端口转发出去

**逆向路径转发**
1. 假设 R 的 *路由表* 中表示了到达各个网咯的最佳路径
2. 数据包 X 从端口 1 到达 R
3. R 检查数据包的来源 S
4. 如果 S 是端口 1 对应的目标网络的最佳路径，则将数据包从其他端口转发出去；否则丢弃
但是该方法不能完全避免重复分组，因为可能存在多条到达目标网络的最佳路径

#### 组播路由
源主机给网络中的一部分主机发送数据包
为每个组建立转发树，从源主机到组成员的路径应该是最佳的
具体步骤：
1. 确定组成员，采用 IGMP:Internet Group Management Protocol 协议
2. 构建生成树(包括源点树和核心树)
   1. 源点树面临的问题：组播源很多时，每个路由器需要生成多棵树，开销大；存储消耗也很大
   2. 核心树：选择一部分节点作为核心，所有流量先汇聚到核心，再分发

隧道技术：可以使组播（多播）数据穿越不支持多播的网络
组播的应用：
1. 音视频会议
2. 数据分发
3. 实时数据组播：球赛
4. 联机游戏与仿真

#### 选播路由
将数据包发送给一个最近的组成员；用户不在乎从哪个服务器获得数据
典型应用：DNS
在没有指定 DNS 服务器的情况下，用户始终链接到最接近的服务器
优点：减少延迟、提供一定程度的负载均衡


### 4.7 SDN
为什么要使用 SDN（SDN 的概念）:
1. 传统的网络设备数据平面、操作系统和网络应用三部分耦合，不同的设备之间不兼容
2. 传统网络不可编程，难以实现高效、按需的数据传输
3. 路由计算效率低，AS 的划分无法从根本上解决问题

#### 流量工程
定义：根据对传输流量的预测，规划流量的传输路径
需要线性规划、网络流算法（需要保证尽可能全局最优）

传统路由的局限场景：
1. 规划指定的路径：基于最短路的传统路由通过调整路径代价可以部分实现，但是这样的调整是有限的
2. 将源到目的的流量拆分为两条路径
3. 让一个路由器区分对待两组流量

#### 软件定义网络架构
技术要点（SDN 的思想）：
1. 基于流表的通用转发
2. 控制平面和数据平面分离
3. 中心化控制平面
4. 应用程序可对网络进行编程开发

#### SDN 数据平面

SDN 交换机：基于流表进行：流量匹配+动作执行
流表由控制器计算并安装，通过流表可以实现流量工程
**流表表项**：头部：用于匹配报文；计数器：表项统计信息；动作：匹配成功后执行的操作
OpenFlow 流表：
1. 模式：报文头部中的匹配值
2. 动作：转发、丢弃、修改报文头部等
3. 优先级：多个表项匹配时，选择优先级最高的
4. 计数器：报文数、字节数


*OpenFlow的局限性*
1. 匹配字段动作固定
2. 不支持“有状态的处理”

**P4: Programming Protocol-Independent Packet Processors**

#### SDN 控制平面
分为 SDN 控制器和 SDN 网络应用
*SDN* 控制器：从南到北分为：通信模块、分布式数据库、接口模块
1. 维护全网状态信息
2. 与数据平面的 SDN 交换机交互
3. 为上层的网络应用提供“北向接口”
4. 以分布式系统的形式实现
5. 可以与 SDN 交换机来自不同厂商

*SDN 网络应用*
实现各类网络功能
可以由第三方开发者提供

**OpenFlow 协议**
用于控制器和 OpenFlow 交换机之间的交互
使用 TCP 传输消息
*控制器->交换机*：读交换机状态、配置交换机参数、修改交换机流表项、通过交换机某个接口发送流表项
*交换机->控制器*：通知流表项已经删除、上报交换机状态、*将匹配失败的报文发送给控制器*

#### 示例
1. 交换机发生链路故障，使用端口状态消息通知控制器
2. 控制器收到消息，更新数据库里的链路状态消息
3. 某个 Dijkstra 路由算法应用通过北向接口注册了对链路状态的监听
4. 回调 Dijkstra 应用，访问相关信息，重新计算路径
5. Dijkstra 路由算法将得到的路径与流表数据库交互，得到新的流表项
6. 控制器使用 OpenFlow 协议发送“修改状态”消息，将新的流表项安装至路由器。

### 4.8 IPv6

动机：32-bit 地址空间不足；简化头部、提升服务质量
* IPv6 地址长度为 128 bit;采用冒分十六进制表示法
* 固定 40 byte 头部,不允许传输途中分片
* 地址化简：有一次机会将连续的 0 替换为 "::"
1. 4bit 版本号
2. 8bit 流量类别
3. 20bit 流标签
4. 16bit 有效载荷长度
5. ……

可以承载多个扩展头部
1. 逐跳拓展头：每个结点都需要检查
2. 路由头：指明转发途中需要经过的结点
3. 分段头：包含类似 IPv4 的分片信息
4. 目的地选项头：仅目的结点需要检查

#### IPv4 到 IPv6 的过渡
>过渡的关键要素：
>1. 尽量保证端到端透明的原则:通信的两个终端主机能够直接建立逻辑连接，中间网络只负责转发数据包，不干预传输语义。(NAT 违反了这一原则)
>2. 高效、可行的编址;地址分配与表示必须：
>   * 易于生成、解析和管理
>   * 不浪费宝贵资源
>   * 与现有 IPv4 体系兼容
>3. 路由可扩展性：随着网络规模扩大路由器规模和复杂度仍然可控
>4. 状态维护:过渡机制是否需要在中间设备维护连接状态，是一个核心取舍。

主流过渡技术：
1. 隧道技术
2. 翻译技术

#### 隧道技术
概念：2 个相同类型的网络设备，跨越中间异构类型网络进行通信

隧道类型：
1. 应用层隧道：SSH 隧道、HTTP 隧道
2. 传输层隧道：TCP 隧道、UDP 隧道
3. 网络层隧道：IPv6 in IPv4，IPv4 in IPv6
4. 链路层隧道: L2TP 协议，PPTP 协议

**IPv6 in IPv4 隧道**
其中 IPv6 使用的源和目的是 IPv6 段的源和目的路由器的地址

问题：报文长度增大导致分片问题
解决：提前分片，需要 Path MTU 发现机制

### 4.9 面相连接增强

#### 虚电路
虚电路是逻辑连接，建立在 Internet 分组交换网络之上
**面向连接**
不一定保证可靠传输
转发策略基于分组标签，即 **虚电路号**
1. 建立连接：
   1. 发送请求分组，接收端发送确认分组
   2. 每个路由器分配一个虚电路号，建立虚电路表项，包括输入端口、输出端口、输入虚电路号、输出虚电路号
2. 实际发送数据时：分组由“数据+目的地址+源地址+标签”组成
3. 释放连接：
   1. 发送方发送拆除分组，接收方发送确认
   2. 路径上的路由器删除相应的虚电路表项

**虚电路与数据报网络的比较**
1. 虚电路可靠性“希望”由网络保证；数据报网络可靠性由主机保证
2. 地址：虚电路使用虚电路号，数据报网络使用 IP 地址
3. 路由选择：虚电路在 *连接建立* 时选择，数据报网络每个分组独立选择路由
4. 分组顺序：虚电路保证顺序，数据报网络不保证
5. 路由器失效：所有经过该路由器的虚电路失效；数据报网络可能丢失分组，但可以选择其他的路径
6. 拥塞控制：虚电路网络容易控制；数据报网络难以控制

#### MPLS（Multiprotocol Label Switching）
MPLS 在 IP 网络中引入了“类似虚电路”的转发机制，但并不改变 IP 的无连接服务模型。
MPLS 设计是为了提升查找速度, 从基于 IP 转发->基于标签转发
每个分组携带一个标签，路由器根据标签进行转发，交换指的是标签的交换
应用：（例如使用标签区分不同 VPN）
1. 面向连接的服务质量管理
2. 流量工程
3. 虚拟专用网 (VPN)

>MPLS 的基本术语:
>1. 在链路层的帧首部和 IP 数据报的首部之间插入一个 4 字节的MPLS 首部, 又称为 2.5 层协议
>2. 标签交换路由器（Label Switch Router, LSR）：MPLS 路由器,具备*标签交换和路由选择*两种功能
>3. MPLS 域，所有相邻的支持 MPLS 的路由器构成一个 MPLS 域
>4. LDP (Label Distribution Protocol)：用来在 LSR 之间建立会>话并传播 Label 映射信息

**转发过程**
1. 进入 MPLS 域时，边界 LSR 根据 IP 头部信息分配标签，插入 MPLS 首部
2. 每个 LSR 根据标签查找转发表，转发数据报，并根据转发表更新标签
3. 离开 MPLS 域时，边界 LSR 去掉 MPLS 首部，恢复为普通的 IP 数据报

**转发等价类**
一组报文在网络上被同样的方式处理，构成一个转发等价类（Forwarding Equivalence Class, FEC）
对一个 FEC 的报文分配唯一的标签

#### VPN（Virtual Private Network）
概念：利用公共网络架设专用网络的远程访问技术

技术背景：
1. 许多机构希望建立专用网络，但是代价昂贵
2. VPN 建立在 Internet 之上，使用加密技术保护数据隐私，保持逻辑上的隔离
3. 设计原则：
   1. 安全性
   2. 隧道与加密
   3. 数据验证
   4. 用户认证
   5. 防火墙与攻击检测

**VPN 的原理**
通过隧道技术在公共网络上模拟出一条点到点的逻辑专线，从而达到安全数据传输的目的
通过在外部数据报文中封装内部数据报文实现隧道
具体步骤：
1. 网关 A 对原始数据报进行 Hash 和加密，将二者的结果合并
2. 将加密后的数据报封装在外部数据报中，发送到网关 B
3. 网关 B 解封装外部数据报，
   1. 通过摘要验证 Hash 值：来源认证
   2. 解密得到原始数据报

### 4.10 网络服务质量
概念：QoS（Quality of Service）指网络在传输数据流时要满足的一系列服务请求，具体可以包括带宽、时延、抖动和丢包率等指标。
在有限带宽的网络中，QoS 允许流量不平等地竞争网络资源

#### 数据包调度
路由器的输出端口决定把缓冲区的哪些数据包输出到链路上
1. 先入先出（FIFO）：简单，但不能区分不同流量
2. 公平队列（Fair Queuing, FQ）：**每个流量** 维护一个队列，轮流发送各个队列的报文
3. 加权公平队列（Weighted Fair Queuing, WFQ）：为每个队列分配权值，轮询时考虑权值
4. 优先级队列（Priority Queuing, PQ）：为不同流量分配不同的优先级，高优先级流量优先发送

#### 流量工程
根据对传输流量的预测，规划流量的传输路径；目的：提高带宽的利用率，减少拥塞
算法：线性规划、网络流算法
需要使用其他技术配合实现：MPLS，SDN进行 **流量区分**
阶段：
1. 路径选择
   1. 一阶路径选择：k-最短路径算法、链路互不相交最短路
2. 流量分配：线性规划
   1. 输入：网络拓扑、网络路径、流量矩阵
   2. 输出路径权重，代表每条流量在每条路径上分配的比例 $D_{(s,t)}$
   3. 约束条件：总比例不超过 1；不超过每条链路的容量
   4. 优化目标：
      1. 最小化最大链路利用率：$\min \max_{e\in E} \frac{流量}{容量}$
      2. 最大化总吞吐：$\max \sum_{s,t\in V}\sum_{p\in \prod_{(s,t)}}\min\{F_{(s,t)}D_{(s,t)},w_p\}$，$w_p$ 为传输速率限制
      3. 最大化满足“源-目的”传输需求：$\max_{a\in [0,1]} \alpha$,  s.t. 
         $\forall s,t \in V, \sum_{p\in \prod_{(s,t)}}\min\{F_{(s,t)}D_{(s,t)},w_p\}\geq \alpha D_{(s,t)}$
   5. 线性规划的局限性
      1. 输入流量的估计依赖经验
      2. 多个目标难以兼容
      3. 线性规划计算量大，难以支持大型网络



#### 流量整形

概念：通过限制流出某一网络的某一连接的流量与突发，使这类报文以比较均匀的速度向外发送

**1. 漏桶算法**：*平滑* 网络的突发流量
到达的数据被放在缓冲区中，按照恒定速率发送出去
如果缓冲区满，新的到达数据被丢弃

**2. 令牌桶算法**：允许突发数据的发送，但是控制流速
1. 产生令牌：周期性向令牌桶中*匀速*添加令牌，如果达到上限，丢弃多余的令牌
2. 消耗令牌：输入的数据包消耗令牌，大数据包消耗的令牌数量更多
3. 判断是否通过：当桶中的令牌数量可以满足数据包对应的令牌数量时，数据包通过，消耗相应数量的令牌；否则数据包被丢弃

#### 综合服务（IntServ）
特点：
1. 面向连接：基于资源预留协议 RSVP(Resource Reservation Protocol) 在主机建立传输流的**连接**
2. 预留资源：逐结点建立或拆除**流的状态**和**资源预留状态**，根据 QoS 进行路由

要求：需要所有路由器支持综合服务；问题：难以实现

#### 区分服务（DiffServ）
概念：在 IP 报头的 8 bit *区分服务字段中* 使用 6 bit *区分服务码点（DSCP）* 进行分组分类，指明分组的类型
路由器在转发这种包时，根据不同的 DSCP 选择相应的调度和转发服务即可

问题：DiffServ 只是一种“相对优先级”的资源分配机制，而不是一种“强制约束与定量隔离”的资源管控机制。DS 字段无法控制网络“公地悲剧”，只要被打上“高优先级”标记，就能持续挤占资源。

> “公地悲剧”：多个自利的流量/用户在共享网络资源（带宽、缓冲区）时，为了最大化自身收益而不断增加发送速率，最终导致整体拥塞、丢包、时延飙升，所有人收益下降。

**对比综合服务与区分服务**
| 维度     | IntServ    | DiffServ   |
| ------ | ---------- | ---------- |
| QoS 粒度 | 每流         | 每类         |
| 信令     | RSVP       | 无          |
| 准入控制   | 有          | 无（或弱）      |
| QoS 保证 | 严格         | 统计 / 相对    |

## 第五部分：链路层

数据链路层的作用是在物理相连的两个结点间进行数据传输。
将比特流划分成帧、差错控制、流量控制
提供服务类型/使用场景
1. 无确认、无连接/误码率低：802.3(以太网)
2. 有确认、无连接/不可靠信道：802.11（WLAN：wireless local area network）
3. 有确认、有连接/长延迟的不可靠信道


### 5.1 链路层基础知识

#### 成帧

**字节计数法**：在帧头部使用一个字段表示帧的长度。缺点：如果该字段出错，接收方无法正确识别帧边界。
**字节填充法**：使用特殊的字节序列作为帧的起始和结束标志。如果数据中出现了该字节序列，则通过插入一个转义字符来区分数据和标志（FLAG->ESC FLAG）。缺点：增加了数据的长度，降低了传输效率。
**比特填充法**：使用特殊的比特序列作为帧的起始和结束标志 0x7E（01111110）。如果数据中出现了该比特序列，则通过插入一个额外的比特来区分数据和标志
>发送方在处理时规定：若出现5个连续的1后插入一个0，在接收方，若出现5个连续的1后，若下一个比特是0，则删除该比特。否则是定界符。

累积确认：接收方只发送对最后一个按序到达的帧的确认。即返回下一个期望的帧序号。

#### 差错检测与修复

通过增加冗余信息来检测和纠正传输中的错误。
检错码：只判断是否出错（用在误码率低的信道）。纠错码:不仅判断是否出错，还能纠正错误（用在误码率高的信道）。

**检错1： 奇偶检验**
偶检验：保证数据中1的个数为偶数。
奇检验：保证数据中1的个数为奇数。
对于二维奇偶校验，可以检测并纠正单个比特错误，检测双比特错误。

**检错2： 校验和**
TCP/IP体系中主要采用的错误检测方法，将数据划分为若干个固定长度的字（如16位）。逐个字相加，（若进位则 +1）发送方最终将结果取反作为校验和。

**检错3： 循环冗余校验 CRC (Cyclic Redundancy Check)**
1. 设原始数据 D 为 m 位二进制串，生成多项式为 r+1 位二进制串 G。G 的最高位为 1，称为生成多项式，收发双方提前商定.
2. 在数据后面添加 r 个 0，得到 m+r 位二进制串。
3. 用 G 对 m+r 位二进制串进行**模2除法**，得到余数 R。
4. 将 R 附加到原始数据 D 的后面 <D,R>，形成最终发送的数据帧。

校验时：如果余数不为 0，则说明数据出错。

**海明距离**
码字：包含数据和冗余信息的二进制串。
码率：数据位数与码字总位数之比。
*海明距离*： 两个码字之间不同的位数。
* 为了检查出 d 个错误，码字之间的最小海明距离至少为 d+1；
* 为了纠正 d 个错误（错误比特数量小于等于 d），码字之间的最小海明距离至少为 2d+1。

*单比特纠错的最低要求*：与任意有效码字的距离为 1 的码字必须无效。两个有效码字距离为 1 的无效码字必须不同。每个 m 位有效信息，实际消耗 n+1 个码字(本身和 n 个无效的邻居)。即 $(n+1)*2^m\leq 2^n$，已知 $m+r = n$，给定 m 可以得到 r 的下界。

**典型纠错码：海明码**

1. 校验位：2 的幂次位：1,2,4,8...
2. 对于第 k 个数据位，将 k 分解为 2 的幂次之和，校验位对应的幂次位置为 1，则该数据位参与该校验位的计算。
3. 得到每个校验位需要关联的数据位(如果第 r 个校验位是第 i 个数据位的一部分)，从而为每个校验位计算值。

如果有 11 个数据位可以使用 4 个校验位。可以根据 P1, P2, P4,P8 是否出错，查询错误列表得到唯一的错误位置。

**典型纠错码：Reed-Solomon码**


#### 访问控制

局域网经典 **信道**：总线拓扑，星型拓扑，环形拓扑；共同点：共享一根信道（别称：广播信道、多路访问信道、随机访问信道）
主要的访问控制方法：
1. 信道划分
2. 随机访问（允许多个节点竞争信道和冲突）
3. 轮流访问（节点轮流使用信道）

**信道划分**：使用在电缆
TDMA （time division multiple access）：等长的时间片给各个站点
FDMA （frequency division multiple access）：将频带划分为多个子信道

*性能分析：*
1. 帧长度平均为 $1/\mu$位/帧，信道容量为 $C$ 位/秒。
2. 帧的平均到达率为 $\lambda$ 帧/秒。
   
单信道平均延迟时间：$T = 1/(\mu C-\lambda)$
信道 N 等分后，平均延迟时间：$T = N/(\mu C-\lambda)$
资源浪费，延迟时间增大。适用于流量稳定且可预测的场景。
CDMA （code division multiple access）：每个站点使用不同的码字进行编码，所有站点同时使用信道。进而允许冲突发生。

> 使用 **Little 定理** 分析信道划分的性能：
> 系统中帧的到达速率为 $\lambda$， 平均服务时间为 $1/\mu $，系统中作业数 n 的稳态概率为 $P_n = (1-\rho)\rho^n$，其中 $\rho = \lambda/\mu <1$。
> 计算平均系统作业数 $L=\sum_{n=0}^{\infty} n P_n = \frac{\rho}{1-\rho}=\frac{\lambda}{\mu-\lambda}$。
> 有 Little 定理 $L=\lambda T$，得到平均延迟时间 $T = \frac{1}{\mu-\lambda}$。


**随机访问**：
使用在以太网、无线局域网
*ALOHA* 若干协议:
1. 纯ALOHA：节点随时发送数据，若发生被破坏后重传。效率分析:
   * N个站点，每个站点在单位时间内的传输概率为p，有数据包成功传输的概率 $Np(1-p)^{2N-2}$
      对 p 求导，$p=1/(2N-1)$, 得到 最大吞吐量 $S_{max} = \frac{1}{2e} ≈ 0.184$。
   * 一个帧时内用户产生的帧 N，信道产生的帧 G。服从泊松分布。
    $P(k) = \frac{G^k e^{-G}}{k!}$, $P(k=0)=e^{-G}$
    $P_0 = e^{-2G}$ 是一帧成功传输的概率，即在 2 个帧时间内没有其他节点发送数据的概率。
    吞吐量 $S= G\times P_0 = G e^{-2G}$ (成功发送的平均帧数)
    当 G=0.5 时，S 最大，最大吞吐量为 1/(2e) ≈ 0.184。

1. 分隙 ALOHA：将时间划分为若干个时隙，节点只能在时隙开始时发送数据。效率分析：
   * $Np(1-p)^{N-1}$，对 p 求导，$p=1/N$，得到 最大吞吐量 $S_{max} = \frac{1}{e} ≈ 0.368$。
   * $P_0= e^{-G}$，$S_{max} = 1/e ≈ 0.368$，效率提高一倍。

*CSMA (Carrier Sense Multiple Access)* 若干协议:
1. 非持续式：监听信道，若空闲则 **立即发送** 数据，若忙则等待 **随机时间** 后重试。
2. 1-持续式：监听信道，若空闲则立即发送数据，若忙则持续监听
3. p-持续式：监听信道，若空闲则以概率 p 发送数据，以概率 1-p 推迟一个时间单元再处理。

> 冲突检测（Collision Detection, CD）：发送数据时持续监听信道，若检测到冲突则立即停止发送，减少信道占用时间。Rx 和 Tx 将信号发往冲突检测模块。不同则认为发生冲突。

4. CSMA/CD：采用 1-持续式 CSMA，并结合冲突检测机制。
   监听信道，若空闲则发送数据，若忙则持续监听。发送数据时持续监听信道，若检测到冲突则立即停止发送，使用 Jam 信号通知其他节点。发生冲突后基于二进制回退决定随机等待的时间 $512*2^k$。
   冲突窗口：$T_{slot} = 2*$Propagation Delay。从发出帧到检测到冲突的最长时间。

>CSMA/CD 效率分析：
>计算平均需要争用多少次才能成功发送一个帧。最优的争用次数为 e ≈ 2.718。
>总争用时间：$e\times 2 t_{prop}$, 也就是浪费的时间
>效率为: $$\frac{t_{trans}}{t_{trans}+e*2t_{prop}} = \frac{1}{1+5*\frac{t_{prop}}{t_{trans}}}$$

**轮流协议**
使用在 蓝牙、光纤

1. 轮询协议：主节点分配信道的使用权，按顺序询问各个从节点是否有数据发送。但是主节点故障会导致整个网络瘫痪，通知会引入延迟，占用带宽。
2. 令牌传递协议：一个特殊的帧（令牌）在节点间（形成环）传递，持有令牌的节点可以发送数据。避免了主节点故障的问题。
3. 位图（预留）协议：*竞争期* 在时间槽发送竞争比特，*传输期* 按位图顺序发送数据。利用率 $= \frac{kd}{N+kd}$, N 为节点数。N 个站点(竞争期需要 N 个时间槽)，k 个站点需要发送数据，每个数据帧长度为 d 位。
4. 二进制倒计数协议：编序号，序号长度相同。竞争期有数据发送的站点从高序号到低序号排队，高者得到发送权。适用于节点数较少的场景。利用率=$\frac{d}{d+\log_2 N}$，二进制编码所需位数是$\log_2 N$位

**有限竞争协议**

低负荷使用竞争法，高负荷使用无冲突协议。
*自适应树搜索*：所有站点构成完全二叉树（不考）


### 5.2 有线局域网

#### 局域网

虽然局域网和子网的定义不同，但是实际相同。
MAC 地址：48 位，前 24 位为厂商标识符 OUI，后 24 位为设备标识符。用于物理上相连的网络接口之间的通信。
MAC 地址可以从一个网络接口移动到另一个网络接口。但是 IP 不行，因为 IP 地址与所属网络有关。
IP地址与 MAC 地址的映射：ARP（Address Resolution Protocol）
如果路由器 R 有两个接口，每个接口都可以有自己的 IP 地址和 MAC 地址。两个接口的 ARP 功能独立。


#### 以太网
**经典以太网**:是有线局域网技术
以太网帧：目的地址与自身地址相同或广播地址时，接收方处理该帧，交付给网络层。
限制最小帧长为 64 字节，保证在最大传播延迟下能够检测到冲突。若帧长小于 64 字节，则填充数据至 64 字节。
> $2*t_{prop}$ 为最晚检测时间，帧的最小长度 $L_{min}$，发送速率为 R，为了能检查到冲突，要求 $L_{min}/R \geq 2*t_{prop}$，即数据从 A 向 B 还没有完全发送就可以检测到冲突，从而停止发送。经典以太网设计中 $t_{prop}\approx 51.2\mu s$，对应 10Mbps 速率下 $L_{min} = 64$ 字节。

64 帧方便冲突检测，如果发送冲突，一定在前 64 字节内检测到。
检查出无效的 MAC 帧，直接丢弃。
服务特点: 无连接、不可靠的数据报服务；多路访问控制采用 CSMA/CD 协议。
>Metcalfe定律：一个网络的价值为节点数的平方或边数。

经典以太网的物理层：使用同轴电缆，10Mbps 传输速率，最大 2500 米。任意两个收发器之间最多允许 4 个中继器串联。使用最多三种以太网技术。
recall: CSMA/CD 中使用二进制指数后退决定随机等待的时间 $\tau*2^k$。$\tau$ 为 512 比特发送的时间。


**以太网的提升**

1. 快速以太网 Fast Ethernet (100BASE-T)：使用双绞线，100Mbps 传输速率。
2. 千兆以太网 Gigabit Ethernet：1Gbps 传输速率。全双工和半双工模式。半双工模式下继续使用 CSMA/CD 协议。流量控制和巨型帧（Jumbo Frame）。
3. 万兆以太网 10 Gigabit Ethernet：10Gbps 传输速率。全双工模式。不再使用 CSMA/CD 协议。


#### 链路层数据交换

集线器使用同一根总线，使用集线器组成的局域网在一个冲突域内。
交换机使用点到点连接，交换机之间使用专用链路连接，形成多个冲突域。内部使用高速背板交换数据。

**逆向学习**：交换机通过学习源 MAC 地址和对应的接口，建立 MAC 地址表。当收到数据帧时，根据目的 MAC 地址查找表，决定将数据帧转发到哪个接口。如果目的地址未知，则广播该帧。
MAC 地址表有 *老化时间* ，防止地址变化导致错误转发。如果发现已经在表中，则重置老化时间。
MAC 地址表的作用：
1. 转发：入境口≠MAC地址表中的出境口，将帧发送到对应的出境口
2. 过滤：入境口=MAC地址表中的出境口
3. 泛洪：MAC 地址表中没有目的地址时，将帧发送到所有端口；或者目的地址为 **广播地址** 时，将帧发送到所有端口

相比于传统 WAN，现在的交换机直连 PC，减少了中间设备，提高了性能。

#### 虚拟局域网技术

可以在一套物理交换机设备上运行多个虚拟局域网（也可以横跨多个交换机）
将交换机上的物理端口进行逻辑分组，每一组端口构成一个虚拟局域网（一个 VLAN）。同一 VLAN 内的端口在链路层上互通，不同 VLAN 之间在链路层上相互隔离，通信需要经过路由。
* 基于 MAC 地址的局域网：根据 MAC 地址划分 VLAN，灵活但复杂。
* 基于协议的局域网：根据网络层协议划分 VLAN，不同协议的流量隔离。
* 基于子网的虚拟局域网：管理员按子网规划 VLAN，对应的端口分配给同一子网。

虚拟局域网的优点：
1. 控制广播范围。
2. 增强网络的安全性
3. 灵活构建虚拟工作组
4. 简化网络管理，提高网络的可管理性

#### 生成树
物理环路的问题：
1. 广播风暴：广播帧在环路中无限循环，导致网络拥塞。
2. 重复帧：同一帧在环路中被多次转发，导致接收方收到重复帧。
3. MAC 地址表不稳定：环路中的帧可能从不同的路径到达交换机，导致 MAC 地址表频繁更新，影响转发性能。

生成树协议（Spanning Tree Protocol, STP）：避免交换机网络中的环路。通过禁用某些端口，形成一个无环的逻辑拓扑结构。
根桥：树的根节点，所有交换机通过交换 Bridge ID 选举出根桥。Bridge ID 由桥优先级和 MAC 地址组成，优先级相同则 MAC 地址较小的交换机成为根桥。
根端口：每个非根桥上到达根桥的最短路径上的端口。（对结点而言）
指定端口：每个网络段上到达根桥的最短路径上的端口。

#### 其他链路层协议
**PPP（Point-to-Point Protocol）**
（区别于以太网协议）
将用户接入运营网络
不支持多点接入，只支持点对点连接。
支持检错，数据压缩，实时检测链路的工作状态。
不支持纠错，流量控制，可靠传输。
链路控制协议（LCP）：建立、配置和测试数据链路连接。
网络控制协议（NCP）：为不同的网络层协议提供配置。

**PPPoE（Point-to-Point Protocol over Ethernet）**
Ethernet 的缺点：安全性低，不易管理
PPP优点：管理简单，支持认证，支持多种网络层协议
结合两者优点，使用 PPP 在以太网上封装数据，实现用户接入。
组网方式：
1. 设备之间建立 PPP 会话。
2. PPP 建立在主机和运营商路由器之间，为每个主机分配唯一的会话 ID。主机上需要安装 PPPoE 客户端软件。

### 5.3 无线网络控制

基站：在有线网络和无线网络之间传输数据的设备。（通常是 Access Point）
无线链路：用于连接基站和移动节点的无线信道。（需要多路访问控制）
**分类**
1. 基于基础设施的无线网络：通过基站连接到有线网络。
2. 自组织无线网络：节点直接通信，无需基站。

根据报文是否经过多个无线链路分类：
* 基于设置设施+单条：蜂窝网， WiFi; 
* 基于设置设施+多条：无线网状网；
* 无设置设施+单条：蓝牙；
* 无设置设施+多条：自组织无线网。

#### 无线链路
无线链路的特点：
1. 信号容易减弱
2. 其他信号源干扰
3. 多个路径传播

衡量指标：两者是负相关的，SNR 越高，BER 越低。
* 信噪比(SNR)：收到信号的强度与噪声强度之比。
* 比特差错率(BER)：传输过程中比特出错的概率。

>**无线链路中多路访问遇到的问题**：无法实现“边发边听”
>>隐藏终端问题：节点 A 和 节点 C 分别位于 节点 B 的两端，A 在 B 的信号覆盖范围内（A 能发给 B），C 也在 B 的信号覆盖范围内（C 能发给 B）。但是，A 和 C 相距太远（或者中间有障碍物），彼此都在对方的信号覆盖范围之外。
>
>>信号衰减：电磁波在空间传播时，随着距离或存在干扰增加，信号强度会迅速减弱。

**CDMA：Code Division Multiple Access（码分多址）**（属于扩频通信）
所有用户采样相同的信道频段，但是每个用户拥有各自的编码机制, 编码正交性--减少干扰。每个比特都被扩展成一个长度为 N 的序列->扩频
编码过程：编码 = 数据 * 码片序列
解码过程：数据 = 编码 * 码片序列 / 码片长度

扩频通信除了直接序列扩频（DSSS）外，还有跳频扩频（FHSS）。

#### 无线局域网 IEEE 802.11(WLAN)
(WiFi 是 WLAN 的一种技术实现方式，WLAN 是概念，WiFi 是具体标准。)
所有都使用 CSMA/CA（Collision Avoidance，冲突避免）协议。都支持基础设施模式和自组网模式。
BSS（Basic Service Set）：WLAN 的最小网络单元
* 基础设施模式：BSS 内有 AP -> 节点通过 AP 通信:
  * 每个主机在发送和接收数据前，必须和一个 AP(Access Point) 建立关联（Association）。
  * 管理员为每个 AP 配置一个 SSID(Service Set Identifier)，用于标识无线局域网。
  * 管理员为 AP 分配一个信道,但是由于信道是共享的，多个 AP 可能使用相同的信道，导致干扰。
* 自组织模式：BSS 内无 AP -> 节点直接通信


**关联过程**：
* *被动扫描*: AP 周期性发送信标帧(beacon frame)，包含 SSID、MAC 地址。主机扫描信道，收到信标帧，选择一个 AP 进行关联。
* *主动扫描*: 主机发送探测请求帧(probe request frame)。AP 收到请求后，发送探测响应帧(probe response frame)，主机选择一个 AP 进行关联。

关联时：主机发送关联请求帧(association request frame)，AP 回复关联响应帧(association response frame)。

#### 多路访问控制

**随机访问 CSMA/CA**
>**发送方**：发送前先监听信道，发送时不再冲突检测。
>* 如果发送前信道空闲时间达到 DIFS (Distributed Inter-Frame Space)，则发送数据帧.
>* 如果信道忙，则选择一个随机值作为计时器，*在信道空闲时开始倒计时* ，信道忙碌时不计时。计时器归零时发送数据帧。
>
>若收到 ACK ，如果有下一帧，继续监听信道；
>若未收到 ACK，设置更大的随机值。监听信道，重复上述过程。
>**接收方**：如果收到一个正确的帧，等待 SIFS (Short Inter-Frame Space) 后发送 ACK 帧。由于是隐藏终端，ACK 是必要的。

**预约机制**: 允许发送方预留信道。
* 发送方使用 CSMA/CA 发送 RTS (Request to Send) 帧，包含数据帧长度信息。
* 接收方收到 RTS 后，等到 SIFS 后**广播**发送 CTS (Clear to Send) 帧。
* 发送方开始发送数据帧其他站点推迟发送数据。
* 在发送完成时，其他站点也能收到 ACK。然后开始倒计时

#### 802.11 帧的地址
* 发送至 AP 时：
  * 地址 1：AP 的 MAC 地址
  * 地址 2：发送方（如 H1）的 MAC 地址
  * 地址 3：最终接收方的 MAC 地址
* 由 AP 发送时：
  * 目的地址：最终接收方的 MAC 地址
  * 源地址：发送方（如 H1）的 MAC 地址

#### 802.11 的其他功能
自适应传输速率：信噪比减小后，降低传输速率，提高可靠性。
功率管理：无线主机通知 AP 进入睡眠状态，AP 缓存数据帧，等待主机唤醒后发送。


### 5.4 无线网络移动

#### 同一子网下的移动
主机的IP 地址不变，MAC 地址不变。但是改变了所在的 BSS。
由于两个 BSS 的 AP连接同一个路由器的不同端口。路由器通过 **逆向学习** 知道这个主机对应哪个端口。

#### 蜂窝网架构
通过移动电话网络，提供移动数据传输
每个小区有一个基站，移动交换中心(Mobile Switching Center, MSC) 负责管理多个基站，处理移动节点的注册、位置更新和呼叫转接等功能。
不同版本的蜂窝网：
1. 2G：完全使用电话语音网络
2. 语音网络架构不变，并行支持数据网络，GGSN（网关支持节点）提供数据网络接入功能
3. 4G: TLE(Long Term Evolution)，完全基于数据网络，取消了语音网络架构，使用 IP 传输语音数据。(不考)

#### 管理移动性：一般方法
移动性术语：
1. 归属网络：每个移动设备有一个长期的归属网络，一般不更换
2. 归属代理：归属网络中 *代表移动设备执行移动性功能* 的实体
3. 永久地址：移动设备在归属网络中的地址，不随位置变化
4. 被访网络（外部网络）：移动设备当前所在的网络
5. 外部代理：外部网络中的实体，代表移动设备执行移动性功能
6. 转交地址：移动设备在被访网络中的地址

当设备不在归属网络中，**设备注册**
1. 设备向外部代理注册，提供永久地址、申请转交地址
2. 外部代理向归属代理通知该设备在自己网络中，提供*转交地址*

**通信方式**
1. 网络中的路由器为设备的永久地址创建路由表项（无法处理大量移动设备）
2. 间接路由：通信者->归属代理->外部代理->设备（对通信者而言是透明的，但是效率较低）
3. 直接路由：
   1. 通信者->外部代理->设备
   2. 通信者需要在最开始通过归属代理 **获得转交地址**
   3. 使用*锚外部代理* ：第一个访问网络中的外部代理作为锚点，后续通信都通过该外部代理转发数据
   4. 到达新的外部网络。新的外部代理通知锚外部代理更新转交地址。


#### 管理移动性：移动 IP (Mobile IP)
移动 IP 允许设备在不同的 IP 子网之间移动，而不改变其 IP 地址。通过使用归属代理和外部代理，实现对移动设备的透明访问。(例如间接路由)

**代理发现**
代理通告 – 外部代理/归属代理通过**广播ICMP通告**，通告代理服务的存在。
代理请求 – 设备发送**ICMP代理请求**报文，然后代理广播通告
在蜂窝网下：
* 归属网路为设备订购服务的网络
* 归属位置注册器（HLR）+ 归属(MSC) = 归属代理
* 访问位置注册器（VLR）+ 访问(MSC) = 外部代理


**切换：同一 MSC，不同基站**
1. 切换由旧基站通知 MSC，提供至少包含一个新基站的列表
2. MSC 通知新基站准备接收移动设备
3. **新基站** 分配无线信道
4. **新基站** 通知MSC与旧基站
5. 旧基站告诉无线设备
6. 移动设备与新基站交换信息
7. 移动用户通知新基站和 MSC 切换完成
8. MSC 通知旧基站释放资源

**切换：不同 MSC**：设备向新的 MSC 注册，新的 MSC通知锚 MSC 设备的位置信息。

**无线与移动性会给上层带来挑战**：
1. 高比特错误率
2. 影响TCP拥塞控制
3. 延迟影响应用
4. 无线带宽的限制

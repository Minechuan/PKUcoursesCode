# Computer Architecture

## 0. 基本知识
CPU 与 GPU 比较：
* 擅长复杂逻辑：处理复杂的条件分支（if-else）、操作系统调度、任务管理极强。
* 低延迟：单核频率高，响应速度极快。
* 通用性：什么任务都能处理（文字处理、网页浏览、系统控制）。
缺点：并行能力弱：不擅长同时处理成千上万个相同的简单计算任务。

计算机的类别：
1. 超级计算机：用于科学计算、气象预测等高性能计算任务，具有极高的计算能力和处理速度。
2. 大型计算机：用于大型企业和机构的数据处理和管理，支持多用户和多任务操作。
3. 小型计算机：规模介于大型计算机和微型计算机之间，适用于中小型企业的数据处理需求。
4. 微型计算机：个人计算机（PC）和嵌入式系统的基础，广泛应用于各种领域。

## 1. CISC 和 RISC

CISC 和 RISC 的区别：
1. 指令集复杂度：
   * CISC（Complex Instruction Set Computer）：指令集复杂，包含大量的指令和寻址模式，单条指令可以执行多种操作。
   * RISC（Reduced Instruction Set Computer）：指令集简化，包含较少的指令和寻址模式，强调每条指令执行单一操作。
2. 指令长度：
   * CISC：指令长度不固定，可能包含多个字节。
   * RISC：指令长度固定，通常为 4 字节。
3. 执行周期：
    * CISC：指令执行时间不固定，复杂指令可能需要多个时钟周期。
    * RISC：大多数指令在单个时钟周期内完成，简化了流水线设计。


### CISC：

#### 80x86
代表芯片：
IA-16：8086
IA-32：80386
IA-64：AMD Opteron 中文名皓龙

**不同模式的区别**
1. 实模式（Real Mode）：16 位寄存器，但是地址总线为 20 位，最大寻址空间为 1MB，适用于早期的操作系统，如 MS-DOS。
2. 保护模式（Protected Mode）：32 位寻址，最大寻址空间为 4GB，支持多任务和内存保护，适用于现代操作系统，如 Windows 和 Linux。
3. 虚拟8086模式（Virtual 8086 Mode）：允许在保护模式下运行多个虚拟的 8086 实模式实例，兼容早期的实模式应用程序。与 8086 相比对 中断 / 异常 的响应处理方式不同。

原始的 8086 使用 **段+偏移** 地址来形成 20 位的物理地址，从而突破 16 位地址总线的限制，实现对 1MB 内存的访问。在保护模式下，使用段选择符和偏移量来计算线性地址，然后通过分页机制将线性地址映射到物理地址。

#### MOV指令的传送方向和限制
1. 段寄存器之间，存储器之间不能相互传送
2. CS 不能作为目的操作数
3. 立即数不能传送到段寄存器

**XCHG**：交换两个操作数，只能是寄存器与寄存器，寄存器与存储器之间交换。寄存器和累加器（AX）交换时，不需要使用寄存器-存储器寻址方式的前缀。
**INC**： 对操作数加 1，不影响标志位 CF，有一种指令长度仅仅占用一个字节。
**XLAT**：查表指令，根据 AL 寄存器的值作为偏移量，从指定的表（由 BX 寄存器指向）中读取一个字节，存入 AL 寄存器中。
**DAA**：十进制调整指令，跟在二进制加法指令之后，将AL中的“和”数调整为 *压缩BCD数* 格式，调整结果送回AL

最长的指令有 15 个字节。
**MOVSB/MOVSW/MOVSD**：字符串传送指令，将 DS:SI 指向的源操作数传送到 ES:DI 指向的目的操作数。传送后，SI 和 DI 根据 DF 标志位自动递增或递减。
DF =0：SI 和 DI 增加
DF =1：SI 和 DI 减少






#### 转移指令

无条件转移指令——直接转移：
1. 短转移：IP = IP + 8 位有符号偏移量
2. 近转移: IP = IP + 16 位或 32（80386）位有符号偏移量
3. 远转移：IP←LABEL的偏移地址；CS ←LABEL的段基值；

段间间接转移：寻址到OPR指定的存储器单元双字，将该双字中的低字送到IP寄存器中，将该双字中的高字送到CS寄存器中


LOOPNE/LOOPNZ指令：CX←CX-1，若CX≠0且ZF=0，转移到LABEL处继续执行；否则结束循环，顺序执行下一条指令。
当 CPU 从内存中取出一个指令后，IP会自动增加，指向下一指令的地址。程序员不能直接对IP进行存取操作，转移指令、过程调用/返回指令等会改变IP的内容。




### RISC：

MIPS:Microprocessor without Interlocked Pipeline Stages
只有Load和Store指令可以访问存储器
缺点：
1. 编程复杂
2. 程序代码量大（同样的程序使用 RISC 和 CISC 指令集，RISC 程序通常更长）
3. 需要优秀的编译器

#### 汇编器提供的伪指令
1. move dst,src => addi dst,src,0
2. 装载地址 la dst,label = > lui dst,upper(label) ; ori dst,dst,lower(label)
3. 装载立即数 li dst,imm => lui dst,upper(imm) ; ori dst,dst,lower(imm) 


#### 指令格式
**R型指令格式**：opcode rs rt rd shamt funct
* opcode: operation code 操作码，指令的前 6 位；在 R 型指令中，该字段恒为 0
shamt: shift amount 如果不是移位指令，该字段为 0

**I型指令格式**：opcode rs rt immediate
lw 指令：rs：基址寄存器，rt：目的寄存器，immediate：偏移量
slti 指令：rs：源寄存器，rt：目的寄存器，immediate：立即数，作用是将 rs 寄存器的值与立即数进行比较，如果 rs < immediate，则将 rt 寄存器设置为 1，否则设置为 0。

MIPS 的 I 型指令中 16-bit位移量可以表示 ±$2^{15}$ words
条件分支：beq 和 bne 指令:
* 分支条件不成立，PC = PC + 4 = next instruction
* 分支条件成立，PC = (PC+4) + (immediate*4)


**J型指令格式**：opcode address
非条件分支指令:
目标地址计算方法（“伪绝对地址”）：PC = ((PC+4) [31:28] | address | 00 )
J型指令的目标地址范围：$2^{28}$ bytes

### RISC-V

#### 指令格式
R 型：寄存器-寄存器操作
I 型：短立即数和访存load 操作
S 型：访存 store 操作
B 型：条件跳转操作
U 型：长立即数操作
J 型：无条件跳转操作

#### 与 MIPS 相比 RISC-V 的优势：
1. 写回位恒定
2. 读端口恒定
3. 转移目标地址形式统一
4. 扩展空间清晰

### ARM指令格式
寄存器编号位域只有4-bit，只能寻址16个通用寄存器
功能位域的位置不统一，给指令译码带来不便
所有的ARM指令都带有4-bit的条件码，都可以条件执行


## 2. 运算部件

### 乘法器

基本的乘法器可以进行并行优化和面积优化

#### Booth算法
把连续的“1”压缩处理，操作对应为“加一次、减一次”，减少部分积的次数。
初始化 A = 0，Q = 乘数，$Q_{−1}$ = 0，M = 被乘数
随后对 [A∣$Q$∣$Q_{−1}$] 进行算术右移（保留符号）


### 移位运算
在一个时钟周期内实现移位，最简单的是将移位器设计为多路选择器，在移 k 位的结果中选择一个期望的结果。

#### 桶式移位器
桶式移位器通过分阶段移位来实现多位移位操作。每个阶段根据控制信号决定是否进行相应的位移。这样可以在较少的硬件资源下实现快速的多位移位操作。
例如 8 bit 桶式移位器有 3 层，每一层有 8 个 2:1 多路选择器：
第一层决定是否移位 4 位
第二层决定是否移位 2 位
第三层决定是否移位 1 位

## 3. 控制器

### 基本控制信号（CISC）
1. LOAD R1 M1
2. ADD R1 M2：将 M2 的内容加到 R1 中
3. STORE R1 M3：将 R1 的内容存储到 M3 中
4. JMP L：将转向 L 处继续执行

### 硬布线控制器设计
组成：
1. 指令译码
2. 微命令编码器
3. 环形脉冲发生器

| 指令名 | T1 | T2 | T3 | T4 | T5 | T6 | T7 |
|------|----|----|----|----|----|----|----|
| **LOAD (00)** | PC_OUT<br>MAR_IN<br>M 读<br>PC 加 | MDR_OUT<br>IR_IN | IR_OUT<br>MAR_IN<br>M 读 | MDR_OUT<br>R1_IN | End |  |  |
| **ADD (01)** | 同上 | 同上 | IR_OUT<br>MAR_IN<br>M 读 | MDR_OUT<br>Y_IN | R1_OUT<br>add | Z_OUT<br>R1_IN | End |
| **STORE (10)** | 同上 | 同上 | IR_OUT<br>MAR_IN | R1_OUT<br>MDR_IN<br>M 写 | End |  |  |
| **JMP (11)** | 同上 | 同上 | IR_OUT<br>PC_IN | End |  |  |  |

用一个逻辑表达式来表示某个控制信号应在什么时间发出、对哪些指令发出：
> MAR_IN = T1·(LOAD+ADD+STORE+JMP)+T3·(LOAD+ADD+STORE)= T1+T3·(LOAD+ADD+STORE)

### 微程序控制器设计
莫里斯·威尔克斯以EDVAC为蓝本设计和建造

每一条机器指令所代表的操作可以被分解为一系列更基本的“微操作”,实现这些微操作的命令信号，称为“微命令”，微命令以代码（微码）形式编成“微指令”。
微命令存储在CPU内部的一个只读存储器（ROM）

> PC_OUT MAR_IN M读 PC加 
> MDR_OUT IR_IN IR_OUT PC_IN 
> R1_IN Y_IN R1_OUT MDR_IN 
> M写 add Z_OUT End

每条微指令对应 16 位 2进制数
若干微指令组成一个微程序，对应处理一条机器指令

#### 构成
1. 控制存储器CM：用来存放微程序，每个存储单元存放一个微指令代码
2. 微指令寄存器μIR：用来存放从CM 中读出的微指令
3. 微地址形成电路：形成下一条微指令的微地址
4. 地址寄存器μAR：保存微指令对应的微地址，指向相应的CM单元

#### 过程
1. 从控制存储器 CM 中读取“取机器指令用的微指令”，使CPU访问主存储器，读取机器指令，送入指令寄存器IR，然后修改程序计数器PC的内容
2. 根据机器指令中的操作码，通过微地址形成电路，找到与该机器指令所对应的微程序入口地址
3. 逐条取出对应的微指令，每一条微指令提供一个微命令序列，控制相关部件的操作。执行完一条微指令后，根据微地址形成方法产生后继微地址，读取下一条微指令。
4. 执行完对应于一条机器指令的一段微程序后，返回到“取机器指令用的微指令”，开始读取与执行又一条机器指令

下址字段如果为 1 xx10 表示需要分支
1001 对应 End 它的下址字段为 0000 表示返回取指令

微程序控制器的优点：
1. 规整：微指令格式统一，便于设计和实现
2. 灵活：修改微程序即可改变指令系统，便于扩展和升级

硬布线的缺点：
1. 设计复杂，调试困难
2. 不易扩展和修改

优点：执行速度快



## 4. Pipeline

超标量处理器：在每个时钟周期内发射多条指令到多个执行单元中并行执行，从而提高指令级并行性和整体性能。第一个商用超标量处理器是 Intel 的 Pentium 处理器。

流水线深度的发展趋势，一度到了 31 级，但是由于分支预测失败的惩罚过大，后来逐渐回落到 14 级左右。
转移指令所占比例：15% - 25%
>转移开销的构成：
>1. 转移条件判定引起的开销
>2. 转移目标地址计算引起的开销

延迟转移（Delayed Branching）技术：在转移指令之后插入一条或多条指令，这些指令在转移发生前执行，从而减少转移带来的性能损失。编译器负责填充这些延迟槽，确保程序的正确性和效率。

转移预测（Branch Prediction）技术：
1. 预测是否转移
2. 预测转移目标地址

### 是否转移预测方法

**硬件方法**
1. 硬件固定预测不转移
2. 编译制导的预测：编译器在生成代码时，根据程序的控制流结构和历史执行情况，插入预测信息，指导硬件进行转移预测。

**软件方法**：
1. 基于偏移的预测：如果转移指令地址和转移目标地址的相对偏移为负值（有可能是循环结束处的转移指令），则预测转移；否则，预测不转移。也就是向后转移预测为转移，向前转移预测为不转移。
2. 基于历史信息的预测（当前普遍采用）：
   1. 1 位预测器：使用一个位来记录上次转移指令的结果。如果上次转移发生，则预测本次转移也会发生；如果上次转移未发生，则预测本次转移也不会发生。
   2. 2 位历史信息：
      * 强发生转移、发生转移、弱发生转移、不发生转移
      * 强发生转移，弱发生转移，弱不发生转移，强不发生转移

随着 N 的变化，当 N >= 4 时 **转移预测正确率** 仍然有提升，但提升幅度变小，硬件开销增加较多，一般采用 2-bit 或 3-bit 历史信息。

### 预测转移地址

**转移目标缓冲器**
BTB: Branch Target Buffer：保存了此前若干次转移指令执行时的目标地址
#### 执行过程
1. 分配 BTB 表项：当取指令时，如果发现该指令是转移指令且 BTB 中没有对应的表项。关于“BTB未命中”的指令根据之后的情况处理：
   * 若此指令实际没有发生转移，则无其它操作
   * 若此指令实际发生转移，则按“预测错误”处理，在BTB中建立一个新表项，设定“历史位”为11
2. 产生转移目标地址：若 **BTB 表项命中** 且 **该指令转移条件判定的预测结果为“发生转移”**，则使用 BTB 中存储的目标地址作为预测的转移目标地址。
3. 修改 BTB 表项：当转移指令执行完毕后，根据实际的转移结果更新 BTB 表项中的目标地址和 **条件判定结果**。

实际上，如果使用 BTB，不需要使用额外的 **是否发生转移** 的预测位，因为 BTB 的存在已经隐含了转移预测的信息。

**进行BTB表项比较的时机**
1. 取指令阶段：在取指令阶段进行 BTB 表项比较，可以提前预测转移目标地址，从而减少流水线停顿的可能性。缺点：每条指令均需要访问，开销大。
2. 译码阶段：在译码阶段进行 BTB 表项比较，可以减少不必要的访问次数，因为只有转移指令才需要访问 BTB。缺点：在流水线较晚阶段获得转移目标地址。结结合流水线的知识，仍然需要一个 Stall 才能取下一条指令。
3. **预译码** 完成后，取址的同时:进行 BTB 表项比较：结合二者的优点。预译码阶段提前确定指令的类型。    




## 5. Memory

### DDR（Double Data Rate）
DDR 是“每拍传两次”
预取是“每次准备更多”
有效频率（对外宣称） = I/O 总线频率 x 2 = 核心频率 x 预取倍数
k 的作用不是提高 I/O 带宽，而是让“慢核心”跟得上“快 I/O”
有效频率 的单位 MT/s = Mega Transfers per second
带宽 = 有效频率 x 总线宽度（通常为 64） / 8 Byte

DDR2：4 倍预取, I/O 总线频率 = 核心频率 x 2 x2 = 100*4
DDR3：8 倍预取, I/O 总线频率 = 核心频率 x 2 x4 = 100*8

**DDR4 SDRAM**
仍然采用 8 倍预取，但是采用了 Bank Group 的设计，将内部的存储单元划分为多个组，每个组可以独立地进行读写操作，从而提高了并行性和数据传输效率。
如果有效频率为 1600 MT/s，则核心频率为 200 MHz，I/O 总线频率为 800 MHz。

### 返回地址栈RAS
过程调用
1. 段内调用：CALL 指令将 IP 压入 RAS 栈顶(注意这里压入的是 CALL 指令的下一条指令的地址，即返回地址)
2. 段间调用：CALL 指令将 CS 和 IP 一起压入 RAS 栈顶

过程返回的优缺点：
* 优点：
  * 均为无条件转移
  * 执行过程返回时，目标地址已知
  * 过程返回指令和过程调用指令一一对应
* 缺点：
  * 每次执行同一条过程返回指令时，预测的目标地址可能不同
  * 转移目标地址在存储器中（PUSH），访问较慢
  * 在流水线晚期才访问存储器获得转移目标地址


## 6. Interupts

第一个带有异常处理的系统：UNIVAC，1951年。算术运算溢出时：转向地址0执行两条修复指令，或者停机。

### Find the address of the interrupt descriptor

在实模式下，内存中的 1MB 地址空间被划分为三个区域：
* 专用区（初始化程序区）：占用了 FFFF0H 到 FFFFFH，CPU 复位后从地址 FFFF0H 取出第条指令，通常是一条无条件转移指令， 转移到系统程序的入口处
* 通用区：占用了 00400H 到 FFFEFH，用来存储一般的程序指令和数据。中断处理的程序储存在这个区域中；
* 专用区（中断向量表区）：占用了 00000H 到 003FFH，存放了 256 个中断处理程序的入口地址（也称中断向量），每个入口地址占用 4B，即 1KB

实模式下：根据中断类型号乘以 4 得到中断向量在中断向量表中的偏移地址，从而找到中断处理程序的入口地址。中断向量表内分别 **从低地址到高地址** 为 **IP 和 CS** 寄存器的内容（注意小端法的保存方式）。
中断服务程序在内存当中的存放顺序并没有要求，但是中断向量表中的中断向量的顺序是固定的。


在保护模式下：
1. CPU 将 **中断类型号x8** 再加上 IDTR 寄存器中的内容，得到中断描述符的地址。
2. 通过该地址可以找到中断描述符中的**段选择符**和**偏移量**。
3. 段选择符会进一步用于索引 GDT（GDTR.Base + 选择符索引 × 8，从而定位到具体的段描述符），获取段基址。
4. 最后，CPU 将段基址和偏移量组合成实际物理地址，跳转到中断服务程序。


### Four interior interrupts

除法中断：0
单步中断：1；一般用于显示 CPU 内部各寄存器的内容和一些其它信息，以便进行调试和发现错误
断点中断：3：一般用于程序调试，在程序中插入断点指令 INT 3，当 CPU 执行到该指令时，产生断点中断，转向调试程序进行处理。
溢出中断：4

其中可以屏蔽的是单步中断，可以通过软件操作 TF 标志来允许（1）或禁止（0）。
除单步中断外，所有 内部中断的优先级都比外部中断高。

### 外部中断优先级的确定方法
1. 软件查询：（由 CPU 处理）
   1. 硬件只需要“或”
   2. 先查询速度较快或是实时性较高的设备
   3. 先查询的优先级较高
2. 硬件中断优先级编码电路
   1. 菊花链优先级排队电路
   2. INTA 是低电平有效，中断响应也是低电平有效
3. 可编程中断控制器：现代PC机中多采用
   1. 当前计算机采用 APIC
   2. APIC 同时分布在 CPU 和南桥中


### 其他中断

**BIOS中断**
BIOS 中断是由 BIOS 提供的一组中断服务程序，主要用于提供对硬件设备的低级访问和控制。常见的 BIOS 中断包括：
* INT 10H：视频服务中断，用于设置显示模式、绘制图形等
* INT 13H：磁盘服务中断，用于读写磁盘数据
* INT 16H：键盘服务中断，用于读取键盘输入，如果键盘缓冲区为空，则等待键盘输入；否则立即返回缓冲区中的数据。

**DOS中断**
DOS 中断是由 DOS 操作系统提供的一组中断服务程序，主要用于文件管理、内存管理等操作系统级别的功能。只有一个类型号，具体的参数通过寄存器传递。常见的 DOS 中断包括：
* INT 21H：DOS 功能调用中断，用于文件操作、内存管理等

### 定时器
* 计数：对外部事件进行计数
* 定时：产生一段准确的时延，定时是对固定的时间单位进行计数

计数器是定时器内的主要部件


#### 8253的初始化操作

8253 内部有 4 个端口（寄存器）可供 CPU 读写：3 个计数器通道（0、1、2）和 1 个控制字寄存器。
| A1 | A0 | 选中的寄存器 | 读/写权限 | 作用 |
| :---: | :---: | :--- | :--- | :--- |
| 0 | 0 | **计数器 0 (Counter 0)** | 读 / 写 | 读写通道 0 的计数值 |
| 0 | 1 | **计数器 1 (Counter 1)** | 读 / 写 | 读写通道 1 的计数值 |
| 1 | 0 | **计数器 2 (Counter 2)** | 读 / 写 | 读写通道 2 的计数值 |
| 1 | 1 | **控制字寄存器 (Control)** | **只写** | 写入初始化命令，设置工作模式 |

1.  **第一步：写控制字（通过 A1A0=11）**
    *   初始化任何一个计数器，必须先往**控制字寄存器**（地址 `11`）写指令。
    *   但是，控制字寄存器只有一个，大家共用。所以，你必须在控制字数据内部（D7, D6 位）指明：**“这条指令是发给谁的（计数器 0、1 还是 2）？”**
    *   此时，**A1A0 用于找到控制端口**，**D7D6 用于在内部路由到目标计数器的配置单元**。

2.  **第二步：写计数值（通过 A1A0=00/01/10）**
    *   配置好工作模式后，你要填入具体的计数初值（比如数 1000 下）。
    *   这时，你直接通过地址线 **A1A0** 选中对应的计数器数据端口。
    *   CPU 把数据直接扔进计数器，芯片根据刚才设定的读写格式（RW1/RW0，比如先低后高）来接收数据。


#### 方式1：计数过程中的暂停和继续
1. CLK：时钟输入信号
   1. 第一个下降沿开始计数，最后一个下降沿结束计数。（下降沿且 GATE 为高时计数器递减。）
   2. 整个计数过程中有 N+1 个下降沿，随后 OUT 信号变为有效
2. GATE：门控输入信号，对计数过程进行控制，具体作用视工作方式而定
   1. 当GATE变低时，暂停计数
   2. 当GATE变高时，开始计数
3. OUT：计数输出信号，“计数到零/定时时间到”输出，输出信号形式视工作方式而定
4. 控制字 WR 低电平有效:
   1. CW 使 OUT 初始化
   2. 设定 N

用途：倒计时：红绿灯、家电控制、秒表等

#### 方式2：分频器
每输入N个CLK脉冲，输出宽度为1个CLK周期的负脉冲（即 N-1 正 ，1 负）

计数初值：18 = 时钟频率/刷新频率 = 1.193182MHz/64kHz
主要用途：脉冲速率分频，如 DRAM 刷新


#### 方式3：方波发生器
对称方波或基本对称的矩形波
N=4 -> 2正，2负
N=5 -> 3正，2负


用方式3产生定时中断: 8253通道0的专用功能
1/时间间隔 = 时钟频率/计数初值 = 1.193182MHz/65536 ≈ 18.2Hz
用方式3控制扬声器发声: 8253通道2的专用功能

主要用途:产生系统的时钟、扬声器发声控制

## 7. I/O 体系结构

### I/O 接口
I/O 接口是连接 CPU 和外设之间的桥梁，负责数据传输和控制信号的管理。具体的功能有：
1. 数据缓冲：I/O 接口通常包含缓冲区，用于临时存储从外设读取的数据或准备写入外设的数据。
2. 数据格式转换：I/O 接口负责将数据从外设的格式转换为 CPU 能够理解的格式，反之亦然。
3. 控制信号管理：I/O 接口生成和管理控制信号，以确保数据传输的正确性和同步性。
4. 状态监测：I/O 接口监测外设的状态，并向 CPU 提供状态信息，以便 CPU 能够做出相应的处理。
5. 中断管理：I/O 接口可以生成中断信号，通知 CPU 外设已经准备好进行数据传输。

### I/O 编址

#### 分开编址
x86采用
I/O 端口地址与存储器地址无关，独立编址，每个 I/O 设备分配一个或多个唯一的端口地址。CPU 通过专门的 I/O 指令（如 IN 和 OUT 指令）访问这些端口地址，从而与外设进行数据交换。
* 直接寻址：端口地址小于 255 可以使用直接寻址方式，通过 8 位端口地址直接访问 I/O 设备。
* 间接寻址：端口地址大于 255 需要使用间接寻址方式，通过寄存器间接访问 I/O 设备。

#### 统一编址
MIPS、ARM 采用
一个地址唯一对应一个单元，无需额外信号指定访问类型。 CPU 使用相同的指令集访问存储器和 I/O 设备。这样简化了编程模型，但可能导致地址空间的冲突和管理复杂性增加。

**优缺点**
统一编址的优点：
1. 可以用访向存储器的指令来访问I/O端口，简化了指令集设计。
2. 简化内部结构和 CPU 引脚数量，降低成本。

缺点：
1. I/O端口占用了一部分存储器地址空间，因而使用户的存储地址空间相对减小
2. 由于利用访问存储器的指令来进行I/O操作，指令的长度通常比单独I/O指令要长，因而指令的执行时间也较长

分开编址的优点：
1. 采用单独的I/O指令，使程序中I/O操作和其他操作 **层次清晰** ，便于理解。
2. I/O 指令地址译码更简单，节省硬件资源。
3. I/O 指令的执行速度更快

>IN 和 OUT 指令执行时间较短，提高了I/O操作的效率。
IN AC, PORT ; 从端口 PORT 读入数据到 AX 或 AL
OUT PORT, AC ; 将把AL或AX的内容输出到外设端口


### I/O 控制

#### 程序控制方式
程序通过轮询方式检查 I/O 设备的状态寄存器，决定是否进行数据传输。CPU 主动查询设备状态，适用于数据传输速率较低且不频繁的场景，但会占用 CPU 资源，效率较低。

无条件传送方式：可以连续传送数据，适用于高速数据传输场景

**条件查询传送方式**
  * 数据输出
    1. 控制字写入控制寄存器
    2. 数据写入 *接口的* 数据缓冲寄存器
    3. *接口* 将数据发到 “并行数据输出” 信号线上，并将 “输出准备好” 信号置为有效
    4. 设备接收数据，将“输出回答”信号置为有效
    5. *接口* 发现 “输出回答” 信号有效后，将 “状态寄存器” 中的状态位 “输出缓冲空” 置为有效
    6. CPU 反复执行指令从 “状态寄存器” 中读出状态字，直到发现 “输出缓冲空”，然后开始下一个输出过程，继续输出 新数据 
  * 数据输入：
    1. CPU 执行指令，将控制字写入接口的 “控制寄存器”，设置接口的工作模式
    2. 外设将数据发到 “并行数据输入” 信号线上，并将 “输入准备好” 信号置为有效
    3. 接口发现 “输入准备好” 信号有效后，从 “并行数据输入” 信号线上接收数据，放入 “输入缓冲寄存器”，并将 “输入回答” 信号置为有效，阻止外设输入新数据。接口将 “状态寄存器” 中的状态位 “输入缓冲满” 置为有效
    4. CPU 反复执行指令从 “状态寄存器” 中读出状态字，直到发现 “输入缓冲满”，然后执行指令从 “输入缓冲寄存器” 中读出数据
    5. CPU 将这个数据读走了，并行接口将 “输入回答” 信号置为无效，同时也会将状态寄存器当中 “输入缓冲满” 这个状态位置为无效，然后等待外设输入新数据

总结：
1. “输出准备好” 是接口到外设的信号，“输入准备好” 是外设到接口的信号。
2. “输出/输入回答”，是外设和接口之间接收方接收数据后的应答信号。
3. 接口与 CPU 之间通过 “状态寄存器” 传递状态信息，输入缓冲寄存器和输出缓冲寄存器是两个独立的寄存器。

优点：
1. 外设要求低
2. 流程清晰

缺点：
1. CPU 占用率高
2. 查询外设状态耗时

#### 中断控制方式
I/O 设备在准备好数据传输时，向 CPU 发送中断信号，CPU 响应中断请求并执行相应的中断服务程序。适用于数据传输频繁且对实时性要求较高的场景，提高了 CPU 的利用率。

数据输入：
1. CPU 执行指令，将控制字写入接口的 “控制寄存器”，设置接口的工作模式
2. 外设将数据发到 “并行数据输入” 信号线上，并将 “输入准备好” 信号置为有效
3. 接口从 “并行数据输入” 信号线上接收数据，放入 “输入缓冲寄存器”，并将 “输入回答” 信号置为有效，阻止外设输入新数据。接口将 “状态寄存器” 中的状态位 “输入缓冲满” 置为有效
4. 接口向 CPU 发送中断请求信号

数据输出：
1. CPU 将控制字写入控制寄存器
2. CPU 将数据写入输出缓冲寄存器
3. 接口将数据发到 “并行数据输出” 信号线上，并将 “输出准备好” 信号置为有效
4. 设备接收数据，将“输出回答”信号置为有效
5. 接口发现 “输出回答” 信号有效后，将 “状态寄存器” 中的状态位 “输出缓冲空” 置为有效
6. 接口向 CPU 发送中断请求信号，CPU 响应中断请求，执行中断服务程序，处理数据传输

> 数据输出和数据输入过程发生的中断使用的是同一个中断向量，进入的也是同一个中断服务程序。

优点：
1. 可以和 CPU 并行工作，提高 CPU 利用率
2. “主动权”：外设可以主动向 CPU 申请服务，满足输入输出的实时性要求。

缺点：
1. 占用 CPU 资源，仍然需要 CPU 参与数据传输
2. 中断处理开销较大，影响系统性能


#### 串行通信与并行通信
串行通信是指数据按位顺序依次传输，每次传输一位数据。适用于长距离传输，减少了传输线的数量，降低了成本和复杂性，但传输速度较慢，易受干扰。
并行通信是指数据按字节或字的单位同时传输，多条传输线同时工作。适用于短距离传输，传输速度快，但需要更多的传输线，增加了成本和复杂性，且易受信号干扰。

在早期由于数据传输的速率较低，并行主要被采用。但是当速率提高时，干扰问题变得严重，串行通信由于其抗干扰能力强，逐渐成为主流。

**差分信号传输技术**
差分信号传输技术通过两根导线传输相反的信号，接收端通过 *比较两根导线的电压差* 来恢复原始信号。这样可以有效抵消外部干扰，提高信号的抗干扰能力和传输距离，广泛应用于高速数据传输场景。
缺点：在电路板上，差分信号一定要走两根等长、等宽、紧密靠近且在同一层面的线，布线难度高

>**8255A 可编程并行接口**
8 bit 控制字：
>* 最高位控制输入输出方式
>* 其他的位会控制不同端口的行为

串行与并行的比较，串行：
1. 传输线数量少
2. 需要经过复杂的串/并转换
3. 同频率下，数据传输率较低
4. 可以避免干扰

### 外部中断的处理

**NMI（非屏蔽中断）**
NMI 是一种高优先级的中断，不能被屏蔽或忽略，通常用于处理紧急情况，如硬件故障或系统错误。NMI 的优先级高于所有其他中断类型。当 NMI 发生时，CPU 会立即响应，保存当前状态并跳转到 NMI 中断服务程序进行处理。

**INTR（可屏蔽中断）**
一般中断请求信号，可以通过设置 CPU 的中断标志（IF）来屏蔽或允许。当 IF 标志被设置为 1 时，CPU 会响应 INTR 信号并执行相应的中断服务程序；当 IF 标志被设置为 0 时，CPU 会忽略 INTR 信号，不会响应中断请求。

PIC（可编程中断控制器）是一种硬件设备，用于管理和控制多个 **可屏蔽外部** 中断请求信号。它接收来自外设的中断请求，并根据优先级和配置决定是否向 CPU 发送中断信号。PIC 可以通过编程设置中断优先级、中断屏蔽等参数，以实现灵活的中断管理。

>8259A 可编程中断控制器：接收到中断请求后，向 CPU 发出中断信号（INT），CPU 响应后发出中断响应信号（INTA）

>现代计算机：键盘中断信号仍连接到中断控制器的 1 号接口。使用多个中断控制器（如 APIC），连接南桥内部和外部的 I/O 接口。每个 CPU 当中，也都带一个中断控制器，可以用于发出中断完成 CPU 间的协同工作。

#### 可屏蔽中断的处理过程
1. 外设发出中断请求，中断控制器向 CPU 发出中断信号（INT）
2. CPU 完成现行指令发出中断响应信号，CPU 向中断控制器发送 INTA（CPU 并不是每时每刻都在看 INTR 引脚。它会在每条指令执行结束后的最后一个时钟周期去采样 INTR 引脚）
3. CPU 读取中断控制器中的中断类型码
4. CPU 压栈相关寄存器，清除 IF 和 TF 标志位，取得中断向量，跳转到中断服务程序。
5. 在中断服务程序中，可在适当时机开放中断（设置 IF 标志位）。
6. 中断服务程序执行完后，执行中断返回指令，恢复寄存器并返回被中断的位置继续执行。

中断嵌套：在执行中断处理程序的过程中，如果允许中断（设置 IF 标志位），则可以响应更高优先级的中断请求，形成中断嵌套。

### DMA 直接存储器访问
DMA 是一种允许外设直接与内存进行数据传输的技术，绕过 CPU 的参与，从而提高数据传输效率。DMA 控制器负责管理数据传输过程，包括地址生成、数据传输和传输完成通知等。
DMA 工作过程：
1. CPU 初始化 DMAC 内部配置寄存器：设置源地址、目的地址、传送时的地址增减方式和传输字节数等参数
2. DMAC 处于空闲状态，等待外设发出 DMA 请求信号
3. I/O 设备发出 DMA 请求信号，DMAC 响应申请
4. DMAC 向 I/O 发起总线读
5. DMAC 将数据写入内存
6. 重复步骤 4 和 5，直到传输完成
7. DMAC 向 CPU 发出传输完成中断信号（可选）

现在有的 I/O 设备本身就带 DMA 功能，不需要单独的 DMA 控制器芯片。
DMA 的使用场景：大量高速数据传输
缺点：
1. 传输少量数据并不高效
2. DMA 控制器使硬件的成本提高

## 8. 总线与总线标准

### 总线的基本概念
组成：传输电路+传输协议
分类：
* 片上总线：连接芯片内部各个模块的总线，如 AMBA 总线
* 系统总线（内总线）：连接 CPU、内存和 I/O 设备的总线，如 PCI 总线
* 外总线（通信总线）：计算机系统之间、或是计算机系统与其他系统，如 USB 总线

总线模块：“挂在总线上”
* Master（主设备）：发起数据传输请求的设备，如 CPU
* Slave（从设备）：响应数据传输请求的设备，如内存和 I/O 设备

**辅助元件**
* 总线译码器：根据地址信号选择对应的从设备
* 总线仲裁器：管理多个 **主模块** 对总线的访问请求，决定哪个主模块可以使用总线

多条总线：由于数据传输速率有明显差异，现代计算机通常采用多条总线结构，如前端总线（FSB）、内存总线和 I/O 总线，以提高整体系统性能。不同总线使用使用总线桥接器来连接。

### 总线协议

总线标准的内容
1. 机械特性：规定模块插件的机械尺寸，总线插头、插座的规格及位置等
2. 电气特性：规定总线信号的逻辑电平、噪声容限及负载能力等
3. 功能特性：给出各总线信号的名称及功能定义
4. 规程特性：对各总线信号的动作过程及时序关系进行说明

#### PCIe
PCI Express，是一种高速串行计算机扩展总线标准，旨在替代传统的并行 PCI 总线。
1. PCIe 采用点对点
2. PCIe 使用差分信号传输技术，提高了抗干扰能力和信号完整性。
3. PCIe 采用全双工的方式，允许同时进行数据的发送和接收，提高了数据传输效率。
4. 串行连接方式，每个设备通过独立的链路与交换机或主板连接，从而提高了数据传输速率和带宽利用率。


总线带宽 = 总线频率×数据位宽×2（全双工），使用“端到端的数据传送方式。
支持多通道（Lane）传输，每个通道由一对发送线和一对接收线组成。常见的通道配置有 x1、x4、x8 和 x16 等，表示使用的通道数量。更多的通道意味着更高的带宽。
一个通道（Lane）由 4 根线组成（2 根发，2 根收，构成差分信号对）。


### 总线的若干场景
以 AHB Advanced High-performance Bus 为例：

#### 从模块插入等待周期的读写数据：
当从模块的 HRDY 信号变为高电平时，表示从模块已经准备好数据，下一个时钟上升沿可以进行数据读/写。在等待周期中，主模块必须保持地址、控制和写数据等信号的稳定。

#### 连续的写数据传输：
* 当主模块在某个时钟周期内发送 **HADDR** 和 Control 后，下一个时钟周期，主模块可以连续发送写数据，同时在这个周期内，将该数据放在 **HWDATA**，同时可以将 **HADDR** 和 Control 信号更新为下一个地址和控制信号。这样就实现了连续写数据传输。
* 但是如果某个周期从模块的 **HREADY**，需要保持 **HWDATA** 不变，因此 **HADDR** 和 Control 信号也需要保持不变，直到 **HREADY** 变为高电平。相应要将数据传输周期拓展：**HWDATA** 的数据的拓展。但下一个数据的地址和控制信号也不得不拓展。
* 直到 **HREADY** 变为高电平的下一个时钟周期，从模块写入数据，在下一个时钟周期，主模块可以继续发送下一个地址和控制信号，同时发送下一个写数据。

#### 大量数据传输

**HBURST** 信号：定义了传输长度和地址变化方式
用于指示传输的突发类型和长度，如 INCR4 表示连续传输 4 个数据，即每个周期如果成功传输，下一个周期的 **HADDR** 会自动递增 4。

**RTRANS** 信号：定义传输中各周期的类型
* NONSEQ 信号：用于表示第一个 burst 传输或单次传输，主模块需要提供完整的地址信息。
* SEQ 信号：在 NONSEQ 之后的连续传输，主模块可以省略地址信息，从模块根据上一个地址和传输大小自动生成下一个地址。
* IDLE 信号：表示当前没有有效传输，主模块不需要提供地址和控制信息。当最后一个数据的 SEQ 传输完成后，主模块可以将 **RTRANS** 信号置为 IDLE，表示传输结束。同时 HBURST 也不需要继续保持突发传输状态。


Burst：一阵短促的射击

#### 场景：地址回卷
**希望先得到Burst传输中的某个特定数据**
WARP 信号：当突发传输到达某个边界地址时，地址回卷信号会被激活，表示地址需要回卷到起始地址。例如，在 4KB 边界上进行突发传输时，如果地址达到 0x0FFF，则下一个地址将回卷到 0x0000。

假设数据宽度为4字节
WRAP16：表示突发传输长度为 16 个数据，地址在达到边界后回卷。即 64 的整数倍地址处。对比：
INCR4: 0x38 0x3C 0x40 0x44
WRAP4: 0x38 0x3C 0x30 0x34

**传输应用举例**
在缓冲中，如果采用关键字优先，可以通过 WRAP 突发传输方式，将关键字所在位置的数据优先传输到处理器中进行处理。


#### 场景：主模块未准备好
HTRANS 设置为 **BUSY**:主设备（Master）在突发传输（Burst）过程中主动插入等待周期（Wait State）
* Master: HADDR、Control 保持不变，HWDATA 不提供写数据。
* Slave: HRDTA 不提供读数据，其他保持不变

#### 场景：需要传输的数据宽度比数据总线小
通过 SIZE 设置地址每次传输的数据量，因此下一个数据的地址递增不一定是 4.
HWRITE：SIZE 会变化，从 Halfword 变为 Word，地址从递增 2 变为递增 4，且第一个递增 4 的这个阶段的第一个数据的 HADDR 发出时会对应 HTRANS 的 NONSEQ 信号。

### 中断 
PCI设备向处理器提交中断请求”与“将数据写入存储器”分别使用了两个不同的路径，处理器系统无法保证哪个信息率先到达

PCI设备保证在数据到达目的地之后，再提交中断请求，遇到的问题是：该方法硬件开销大，不容易实现，还将增加中断请求的延时

**读刷新方法**：中断服务程序先读取PCI设备中断状态寄存器，判断中断产生原因后，才对PCI设备写入的数据进行操作。一方面可以获得设备的中断状态，另一方面是保证DMA写的数据最终到达存储器。如果不这样做，就可能产生数据完整性问题

**MSI中断机制**：
MSI（Message Signaled Interrupts，消息信号中断）是一种现代计算机系统中用于处理设备中断请求的机制。与传统的中断方式不同，MSI 通过在内存地址空间中写入特定的数据来触发中断，而不是使用专用的中断线。
当设备向一个特殊地址写入时，会向CPU产生一个中断，即MSI中断
优势：
1. 解决了多个设备共享中断信号的问题
2. 解决了每个功能设备只支持一个中断的问题
3. “异步”中断的数据完整性问题：使用MSI时，产生中断的写不能越过数据写，中断服务程序可以确信所有数据已经到达内存
